Before the Shake: App Map

A take-home guide to the code. Snapshot of source commit d6e4ab4; the code can drift after this.

What the app is

A calm interview about a household in an Istanbul flat that ends in one printable card: what to do this week, questions for an engineer, and what the app cannot judge. Four pieces do the work:

  • Rules (public/lib/rules.js) decide which actions go on the card and in what order. No model is involved.
  • Fixed text (public/lib/content.js, questions.js, sources.js) is everything offline mode shows.
  • The fence (public/lib/validate.js, public/lib/emergency.js) decides what Claude's wording may change, and stops the flow for an emergency without asking the model.
  • Live mode (server/claude.js, server/prompts.js) asks Claude for wording only, through the local server.

One action: "Make my card" in live mode

Reference route (3 stops)

A reference route through the finished code, not a record of a completed tour.

  1. public/app.js, search async function writeCard and async function askClaude. The card appears straight away with the fixed explanations. askClaude sends only the rule output to /api/claude, with a 30 second timeout. Any network error, timeout or error reply calls goOffline(): the badge changes, the notice appears, and the answers stay.
  2. server/claude.js, search card: (. The server refuses a card with any action, household or why id the app does not know before calling Claude, then builds the prompt input from the app's own titles and lines (ACTIONS, VARIANTS, WHY), not from raw answers. The JSON schema from cardSchema(ids) in server/prompts.js limits ids to the card's own. A stop_reason other than end_turn, text that does not parse, or a failed check all return { error }.
  3. public/lib/validate.js, search export function checkCardText. The fence itself: the id list must equal the rule output exactly and in order, each explanation is 1 to 240 characters, and digits, % and phrases such as "building is safe" are refused. Titles, order, sources and engineer questions never come from the model, so passing this check is enough.
The same idea for the emergency stop

public/lib/emergency.js, hasEmergencyKeyword runs in the browser before any model call. combineFlags joins it with the model's flags using OR, so the model can add an emergency but never clear one. test/claude.test.js has the case where the stub says "no emergency" for "I smell gas" and combineFlags still returns an emergency, so the 112 screen opens.

A practice to reuse

Let the model write only into slots the app owns, then check the slots and test every way it can fail. Here the rules choose the action ids; Claude may only fill in an explanation per id; checkCardText compares ids, not reworded text, and four failure forms (API error, refusal or max_tokens, unparseable text, JSON that fails the check) all land on the same fixed wording. test/claude.test.js drives each form through a stubbed SDK client, so it runs without a key.

One limit showed up in the build: data-level tests passed while the page printed "[object HTMLHeadingElement]" for the official-process block. The browser run caught it (final review, laptop run 1). Since then cardView keeps the card as plain data that a test can read, and the browser run checks what a person actually sees. On another project the same pair applies: a test on the data the model is allowed to touch, and one check on the screen people read.

Still open: with no API key on the build server, the real model has not run yet. Whether the fast model accepts effort: "low" (spec change C2) is shown by the first live run; server/claude.js retries once without it if the API refuses. The check also reads words, not meaning: it now refuses common reassurance ("should be fine", "hold up", "solid"), but a reassuring sentence in other words would still pass. The emergency phrases are English only.

Run it again

npm ci, then npm start, then open http://localhost:3000. Without a key it runs in offline mode. For live mode, copy .env.example to .env and set ANTHROPIC_API_KEY. Tests: npm test.
